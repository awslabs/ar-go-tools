# Dataflow Summary Generation Task

You are tasked with generating dataflow summaries for Go functions to be used with the Argot taint analysis tool. A dataflow summary describes how data flows through a function - which inputs affect which outputs.

## Dataflow Summary Format

Generate summaries in YAML format using this structure:

```yaml
dataflow-summaries:
  - package: "<package name>"
    function: "<function name>"  # for standalone functions
    receiver: "<struct name>"    # for methods (with method field)
    method: "<method name>"      # for methods only
    flows:
      - from: "<source>"
        to: "<destination>"
```

## Flow Identifiers

Use these identifiers to specify data flow sources and destinations:

- `!arg 0`, `!arg 1`, etc. - Function arguments by position
- `!arg <name>` - Function arguments by name
- `!receiver` - Method receiver (methods only)
- `!ret`, `!ret 0`, `!ret 1`, etc. - Return values by position

For methods, argument indexing starts after the receiver:
- In `func (r Receiver) method(x, y int) string`, `x` is `!arg 0`, `y` is `!arg 1`

## Complex Data Flows

For flows through struct fields, arrays, or maps, use parentheses and suffixes:

- `(!arg 0).field` - Flow through struct field
- `(!ret 0)[*]` - Flow through array/slice/map elements
- `(!arg <x>).field1[*].field2` - Nested field and element access

For maps, `[*]` represents flow to both keys and values (no distinction possible).

## Task Instructions

1. **Analyze the function**: Understand what the function does and how data moves through it
2. **Identify flows**: Determine which inputs affect which outputs
3. **Be conservative**: Include all possible data flows to ensure soundness
4. **Consider all paths**: Account for all execution paths (branches, loops, error cases)
5. **Handle mutations**: If arguments are modified, include flows back to them

## Examples

**Simple function:**
```go
func concat(a, b string) string {
    return a + b
}
```
Summary:
```yaml
dataflow-summaries:
  - package: "mypackage"
    function: "concat"
    flows:
      - from: "!arg 0"
        to: "!ret 0"
      - from: "!arg 1"
        to: "!ret 0"
```

**Method with field access:**
```go
func (u *User) GetFullName() string {
    return u.FirstName + " " + u.LastName
}
```
Summary:
```yaml
dataflow-summaries:
  - package: "mypackage"
    receiver: "User"
    method: "GetFullName"
    flows:
      - from: "(!receiver).FirstName"
        to: "!ret 0"
      - from: "(!receiver).LastName"
        to: "!ret 0"
```

**Function modifying arguments:**
```go
func appendToSlice(slice []string, item string) []string {
    slice = append(slice, item)
    return slice
}
```
Summary:
```yaml
dataflow-summaries:
  - package: "mypackage"
    function: "appendToSlice"
    flows:
      - from: "(!arg 0)[*]"
        to: "(!ret 0)[*]"
      - from: "!arg 1"
        to: "(!ret 0)[*]"
```

## Important Notes

- **Soundness**: Your summary must be conservative - include all possible flows
- **No validation**: There are no automated tools to check summary correctness
- **Error handling**: Consider flows through error return values in Go's `(result, error)` pattern
- **Mutations**: If the function modifies input arguments, include flows back to them
- **All execution paths**: Consider branches, loops, and error conditions

## Analysis Tools Available

Use these argot analysis tools to understand the function before generating the summary:

1. **`argot_load`** - Load the program first (required)
   - Use the full path to the Go file: `argot_load ["/path/to/file.go"]`
   - For directories with multiple main functions, load individual files

2. **`argot_list_functions`** - List functions matching a regex
   - Use it to find the information of the function.
   - The user may have given imprecise package and function name information, this allows you to find the specific function.
   - You can search for <package_name>.*<function_name>.* or the like (use package to filter down).
   - If there are multiple choices, you must come back to the user to allow them to make a selection.

3. **`argot_show_src`** - View the source code
   - Use function name regex: `argot_show_src <function_name>`
   - Helps understand the function's logic and structure

4. **`argot_show_ssa`** - View SSA (Static Single Assignment) representation
   - Use function name regex: `argot_show_ssa <function_name>`
   - Shows precise data flow operations and variable assignments
   - Critical for understanding how data moves through the function

5. **`argot_run_pointer`** - Run pointer analysis for aliasing information
   - Provides aliasing information crucial for understanding data flow
   - Must be run before using pointer-dependent analysis tools
   - Takes some time but provides essential information for complex functions

6. **`argot_function_focus`** - Focus on specific function for detailed analysis
   - Use function name regex: `argot_function_focus <function_name>`
   - Enables use of value-specific analysis tools

7. **`argot_show_ssa_value`** - Examine specific SSA values (requires focused function)
   - Use SSA variable names from the SSA output (e.g., `t7`, `input`)
   - Shows type information, instruction details, and referrers
   - Helps trace how values flow through the function

## Workflow

1. Load the program with `argot_load`
2. List matching functions with `argot_list_functions <function regex>`
3. View source code with `argot_show_src` to understand the function
4. View SSA representation with `argot_show_ssa` to see data flow operations
5. Run pointer analysis with `argot_run_pointer` for aliasing information
6. Focus on the function with `argot_function_focus` if detailed analysis is needed
7. Use `argot_show_ssa_value` to examine specific values if focused
8. Generate the YAML dataflow summary based on your analysis

## Required Arguments

To generate a dataflow summary, you need:

1. **File path** - A path to the main files of the program using the function. This is the path for the program to load, no the function to analyze.
2. **Function name** - Name of the function to analyze
3. **Package name** - Package containing the function
