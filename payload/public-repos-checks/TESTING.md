## Testing and Comparing Summary Generation with Direct Taint Analysis

This folder contains sample Go repositories for which we have defined taint analysis problems. For those taint analysis problems we want to compare to analysis approaches:
- running the taint analysis approach from scratch.
- running the summary generator and then running the taint analysis with the generated summaries.


## Taint analysis problems

In each of the valid directories, we have a config file `argot-config.yaml` file that defines taint analysis problems for the Go repository. On top of the taint analysis problems, the file has a section that points to another yaml file where all the dataflow summaries are defined:
```yaml
dataflow-problems:
  user-specs:
    - user-specs.yaml
```
The config file points to the `user-specs.yaml` file, who should be present next to the config file. All the dataflow summaries defined (by the user, or generated by us) will then be used during the taint analysis.

## Running the taint analysis from scratch

In this setting, we assume that the `user-specs.yaml` file is completed by the user. If it is empty, then that means there is no summary to be specified. We run the taint analysis as follows:
```sh
argot taint -config argot-config.yaml
```
The taint analysis tool will pick up the summaries where they are. We should run the taint analysis with a reasonably long timeout and then collect the final answer of the taint analysis tool, which will tell us all the dataflows that are present. For most of the problems we do not expect any alarm to be raised, but there can be timeouts because without the summaries the taint analysis will need to explore many functions, and potentially functions that are hard to analyze. There will be also alerts about unsound functions; for example functions that use unsafe or reflect features from Go.

## Generating summaries and then running the taint analysis

In this setting, we assume that the `user-specs.yaml` file is initially empty, but we know which functions need to be summarized. Those functions will be specified in a `to-summarize.json` file in the same folder as the config file.
We first need to call the dataflow summary generator on this file and with the config (that specifies how to load the program to analyze).
An easy way to call the summarizer, provide you want to use LLMs on Bedrock and you have installed the argot tools (`make install` and `make mcp-install`), is to call:
```sh
AWS_PROFILE=<your-profile> argot-summarize --config argot-config.yaml --functions to-summarize.json
```
